01 / A question, with a paper trail

Research is a process.
Keep the process visible.

For developers exploring agentic research: Loopaer keeps plans, source findings, verification and human controls in one inspectable workspace. This is a code-grounded illustration, not a recording of a successful research run.

Read the transcript / no-video walkthrough
  1. 0:00 — Start with a question. A developer creates a session. The runtime emits SessionCreated. The example question, “How should we evaluate source quality?”, is synthetic and contains no private session data.
  2. 0:06 — Make the work inspectable. The planner uses OpenRouter to request a task graph. PlanReady and ReasoningTreeUpdated carry the result to the workspace. Fallback planning exists when model output cannot be parsed.
  3. 0:12 — Follow the sources. Research queries arXiv and GitHub, then asks the model to extract facts, entities and gaps. SourceFetching and FactExtracted are observable events, not guarantees of useful findings.
  4. 0:20 — Ask what holds up. Verification asks the model to assess facts against collected sources. ConfidenceChanged reports a model judgment, not calibrated truth. The skill builder packages knowledge as a portable skill. Pause, resume, cancel and inject are cooperative controls on active loops.
  5. 0:26 — Keep the boundary honest. React talks to FastAPI. The event bus fans out to WebSocket subscribers and persists events when a database is available. MongoDB supports the broader runtime. The command-center engine is separate: six scripted stages, mocked connectors and invented outcomes. In-memory demo mode is not a complete runtime substitute.

Architecture notes / static alternative
React workspace
App.js preserves landing, auth, runtime, diff and snapshot routes.
FastAPI + loops
server.py routes requests; runtime.py schedules planner, research, verification and skill-builder tasks.
Sources + model
sources.py queries arXiv/GitHub. openrouter.py streams model output. Availability and model quality vary.
Event bus
eventbus.py buffers and broadcasts events; persistence is conditional on a database. WebSocket is /api/ws/{sid}; the demo uses a run ID in the same route.
MongoDB
Required for the full runtime API, including direct database access in sessions, skills, auth, generated UI and snapshots. Demo fallback is narrower.
Scripted demo
commandcenter.py advances Intake, Plan, Connect, Reason, Verify and Deliver with timed events, not enterprise integrations.

03 / The demo is not the research loop

Tour the scripted pipeline

These six steps describe the command-center simulation. Use the step buttons or read the ordered list. This tour does not start a backend run.

Choose a step, or read all six below.

  1. Intake. A fixed scenario supplies a synthetic brief.
  2. Plan. The scripted engine narrates a work sequence.
  3. Connect. Connector names are mocked catalog entries; no enterprise system is queried.
  4. Reason. Progress is timed; this engine does not perform the runtime's model-driven research.
  5. Verify. The demo advances to another stage, not independent validation.
  6. Deliver. Completion ends the scenario. Invented outcome figures are not measured results.
