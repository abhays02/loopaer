# Plan: Enable the frontend to animate the Enterprise AI Transformation Platform from live backend content and pipeline events
**Complexity:** Medium — new platform module with several content endpoints plus a pipeline event engine feeding websocket/SSE consumers; interface must be stable before implementation.

## Goal
Enable the command center frontend to render use-case, connector, pillar, and outcomes content and to animate an orchestration pipeline end to end from live backend events, without breaking the existing runtime contract or requiring MongoDB.

## Deliverables
- API endpoint: GET /api/platform/use-cases — use-case library with original demo copy → feeds section 4 of the landing experience
- API endpoint: GET /api/platform/connectors — mocked enterprise connector catalog → feeds the integrations visual
- API endpoint: GET /api/platform/pillars — differentiation pillars content → feeds section 3
- API endpoint: GET /api/platform/outcomes — outcomes demo data with invented-for-demo values only → feeds section 5
- API endpoint: POST /api/platform/pipelines/run — starts a demo orchestration run and returns run id plus stage list → drives the pipeline centerpiece animation
- Event stream: pipeline stage events emitted over the existing websocket route /api/ws/{run_id} and a new SSE route GET /api/platform/pipelines/{run_id}/stream → frontend animates flows live
- API endpoint: GET /api/platform/pipelines/{run_id} and GET /api/platform/pipelines/{run_id}/events — run state and event replay → supports reconnect and scrubbing
- API endpoint: GET /api/platform/health — storage mode (mongo or in-memory fallback) and engine status → frontend can degrade gracefully
- Behavior: MongoDB is optional; when unreachable the server boots and all platform endpoints work from in-memory state → demo runs anywhere
- Document: docs/backend-api.md — the API contract for the frontend → downstream integration reference
- Tests: tests/test_platform_api.py — unit/integration coverage of endpoints and the pipeline engine

**Out of scope:**
- Any change to existing session, auth, diff, snapshot, skills, memory, or genui endpoint contracts (AC-10 of the product brief)
- Real connector integrations; all connectors are mocked demo content
- Frontend work

## Acceptance Criteria
| ID | Type | Criterion |
| --- | --- | --- |
| AC-1 | Happy path | Given the server is running, when the frontend calls each platform content endpoint, then it returns 200 with non-empty, humanized, emoji-free payloads |
| AC-2 | Happy path | Given a pipeline run is started, when the client subscribes to the websocket or SSE stream for that run, then it receives stage lifecycle events in stage order ending in a completed event |
| AC-3 | Edge case | Given a pipeline run finished, when a late client requests event replay, then it receives the full ordered event history |
| AC-4 | Error path | Given MongoDB is unreachable or unconfigured, when the server starts, then platform endpoints and the pipeline engine still function from in-memory storage |
| AC-5 | Regression | Given the rebuild, when the existing API surface is inspected, then all pre-existing routes and the /api/ws/{sid} contract are unchanged |
| AC-6 | Non-functional | All numbers in outcomes data are invented demo values; no competitor-derived metrics; all copy original and emoji-free |

3. Write unit/integration tests in `tests/test_platform_api.py` covering AC-1 through AC-5
