Reproduction (from repository root)
  cd docs/showcase
  npm ci
  npm run serve
  Open http://127.0.0.1:8765/docs/showcase/
  In another terminal, from docs/showcase:
  CHROMIUM_PATH=/usr/bin/chromium npm run render

  Renderer binds 127.0.0.1:8766; requires that port to be free. Temporary
  frame PNGs go in the OS temp directory and are removed in finally.
  Preview uses a curated temporary snapshot of explicit showcase/source files,
  not the checkout. Env files, credentials, .git and unrelated session evidence
  are never copied. Direct /.git/config and /backend/.env requests return 404.
  Snapshot is removed on shutdown; restart the preview after source edits.
  Fonts/scenes are captured locally using Chromium at 960x540, 24 fps.
  MP4: libx264, CRF 23, preset slow, yuv420p, faststart.
  WebM: libvpx-vp9, CRF 33, zero target bitrate, deadline good, cpu-used 2.
  GIF: same timeline condensed to 12 seconds, 12 fps, width 800,
  64-color diff palette, no dithering, infinite loop.
  Contact sheet: fps=3/16, scale=480:-1, tile=3x2 (six filled cells).
  Exact encoding commands are in render.mjs. Encoding is reproducible
  with the recorded tool versions; other versions may produce different bytes.

Accessibility / claims limitations
  Native video controls, no autoplay, local VTT captions and full transcript.
  Chapter links work as transcript anchors without JavaScript; with JS they
  pause and seek the film. Node buttons expose pressed state and a live detail
  region. Pipeline step descriptions are also announced and remain in a list.
  Static diagrams default on with prefers-reduced-motion. Video playback is
  still user-controlled; the diagrams have no independent automatic timeline.
  360px layout keeps readable copy and >=44px controls. The wide sketch pans
  within its own frame; a text architecture alternative is always available.
  GitHub Markdown cannot pause a GIF or honor a script-based reduced-motion
  toggle. A static poster is linked alongside the preview; use it instead.
  No script, iframe, custom CSS or plugin is expected to run in GitHub README.
  "Explore" on GitHub opens source, not an invented hosted application.
  The snapshot preserves root-relative source/font paths. Opening index.html
  directly as file:// is not the supported module workflow.
  Python's simple HTTP server lacks byte-range support; WebM played but did not
  seek in checked browsers. Use the documented npm server for chapter scrubbing.
  Light/dark screenshots use GitHub-like surrounds, not an actual hosted
  GitHub capture. The opaque dark poster retains the same contrast in both.
  The walkthrough is silent and uses illustrative events, not provider output.
  This system Chromium lacks H.264 decoding; Google Chrome supports the MP4.
  The tour prefers WebM, which also plays in the checked system Chromium.
  Password hashing works via the system crypt backend here; requirements do
  not explicitly install bcrypt. Other platforms may need a compatible bcrypt
  package. Full signup/auth integration has not been tested.
